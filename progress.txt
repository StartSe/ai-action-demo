- **Learnings for future iterations:**
  - Primeiro uso de `<elevenlabs-convai>` (widget embutido) na suíte: em React 19.2.8 (`@types/react` correspondente), o namespace `JSX` mora dentro de `declare namespace React {}`, não mais solto no escopo global — a declaração de um elemento customizado precisa ser `declare module "react" { namespace JSX { interface IntrinsicElements {...} } }` (não `declare global { namespace JSX {...} }`, que não compila mais para esta versão). Sem isso o TypeScript não reconhece `<elevenlabs-convai>` como JSX válido.
  - Detectar quando um widget de terceiros (custom element) injetado por script está pronto: `customElements.whenDefined("<nome-do-elemento>").then(() => setState(true))` funciona tanto para o script recém-injetado quanto para quando ele já existe (checagem via `document.getElementById` antes de criar a tag) — e, por rodar dentro de um `.then()`, não dispara `react-hooks/set-state-in-effect` (que dispara para um `setState` síncrono direto no corpo do efeito, mesmo dentro de um `if` claramente condicional).
  - Uma "sondagem até a análise chegar" (`GET .../ultima?desde=<idAnterior>`) não precisa de nenhum estado de "sessão" no servidor: basta o cliente guardar, antes de começar a esperar, qual era o último resultado conhecido daquele recurso (aqui, `sala.ultimoResultadoId`) e comparar; o servidor só compara o valor atual com o `desde` recebido. Reaproveitável por qualquer fluxo futuro onde um resultado chega de forma assíncrona por um canal fora do controle da própria requisição (webhook, fila, etc.).
  - Reconfirma o padrão já registrado em `entrevista-ia/CLAUDE.md` (US-058): um componente que precisa manipular algo cujo back-end chama "token" deve usar outro nome (aqui, `codigo`) em toda a extensão do arquivo — `scripts/verificar-jargao.mjs` varre `components/*.tsx` inteiro (não só texto visível), então até um nome de prop/variável dispara o alarme, não só texto renderizado.
