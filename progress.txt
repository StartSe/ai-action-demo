## Codebase Patterns
- Todos os 10 apps (pdi-time + agente-kanban, contratos-ia, entrevista-ia, financas-ia, posts-sociais, prospeccao-ia, reunioes-ia, voz-do-cliente, whatsapp-atendente) replicam o mesmo esqueleto de `app/page.tsx`: um `useRef` guarda ("autoEnviado"/"autoIniciado") mais um `useEffect([])` que lê `?exemplo=1` da URL e dispara o fluxo via `setTimeout(..., 0)`. Mudanças nesse padrão devem ser copiadas sem alterar nos 10 apps (regra do PRD).
- Cada app roda `next dev` na porta 3000 (não há porta fixa 3001 como o texto de uma acceptance criteria sugere); usar `PORT=xxxx npm run dev` se precisar rodar vários em paralelo.
- Não há script de typecheck no package.json; usar `npx tsc --noEmit -p tsconfig.json` dentro da pasta do app.
- Para verificar comportamento client-side sem servidor de browser MCP: `chromium --headless --disable-gpu --virtual-time-budget=8000 --dump-dom "<url>"` roda timers/fetches por Xms antes de despejar o DOM final — útil para confirmar que o atalho `?exemplo=1` realmente chegou ao estado "pronto" (procurar `class="reveal"` ou texto do resultado).
- Para `--screenshot`, adicionar sempre `--run-all-compositor-stages-before-draw`: sem essa flag o chromium headless às vezes despeja a captura com a animação `.reveal` (fade-in) presa a meio caminho (opacidade baixa), deixando a tela toda "apagada" mesmo com `virtual-time-budget` alto. Com a flag, a captura sai no estado final real. **Atualização (US-014):** essa flag sozinha nem sempre resolve — `--virtual-time-budget` é tempo virtual para timers JS, não tempo real de compositor, então a transição CSS de 0,45s pode não ter "tempo real" suficiente para terminar mesmo com budget alto (8000, 15000...). Adicionar também `--force-prefers-reduced-motion` é a forma determinística de eliminar o problema (`globals.css` desliga `.reveal` via `@media (prefers-reduced-motion: reduce)`), preferível a só aumentar o budget.
- Nem toda user story precisa que `Destaque` (componente de US-005) seja usado no `Resultado` de todo app: o PRD (linha ~238 de `tasks/prd-ui-ux-executivos.md`) só lista um "dado principal" natural para Contratos (nota de risco), Voz do Cliente (NPS), Financeiro (total do período), Entrevistadora (nota) e Ata (contagem de decisões/ações). `pdi-time` não tem um número único que decida, então a AC "Destaque (quando houver)" é satisfeita criando o componente em `ui.tsx` sem chamá-lo no `Resultado` do pdi-time.
- `ui.tsx` agora exporta os helpers pt-BR `numero(n, casas)` e `data(d, { comHora })` (US-006); qualquer formatação nova de número ou data em qualquer app deve usar esses helpers em vez de `Intl` direto, para manter os 10 apps consistentes quando a fundação for replicada (US-017+). `data()` omite o ano quando a data é do ano corrente.
- Next.js 16 (`node_modules/next/dist/docs/`) neste projeto: `params` de `page.tsx`/`route.ts` dinâmicos é `Promise<...>` (precisa `await`), e o jeito tipado é o helper global `PageProps<'/rota/[id]'>` (ou `RouteContext<'/rota/[id]'>` em `route.ts`) — não precisa importar, mas só existe **depois** de gerar os tipos (`npx next typegen`, ou qualquer `next dev`/`next build`); rodar `tsc --noEmit` logo após criar uma rota dinâmica nova falha com "does not satisfy the constraint 'AppRoutes'" até rodar o typegen uma vez. `notFound()` de `next/navigation` dentro de um Server Component (`page.tsx` sem `"use client"`) devolve HTTP 404 de verdade para requests não-streamed (confirmado com `curl -o /dev/null -w "%{http_code}"`); o texto amigável fica em `not-found.tsx` no mesmo segmento de rota.
- `components/ui.tsx` inteiro é `"use client"`; funções puras de formatação (`numero`, `data`) exportadas de lá **não podem ser chamadas diretamente** de um Server Component (`Error: Attempted to call data() from the server but data is on the client`) — só podem ser renderizadas como componente (`<Origem meta={...} />` funciona de um Server Component, `data(x)` não). Por isso `numero`/`data` moraram para `lib/formato.ts` (arquivo puro, sem `"use client"`), reexportados por `ui.tsx` para não quebrar quem já importa de lá; Server Components (como páginas de impressão/leitura) devem importar esses helpers direto de `@/lib/formato`. Ao replicar essa fundação para os outros 9 apps, copiar `lib/formato.ts` junto com `ui.tsx`.
- CSS Paged Media: para aplicar `size`/`margin` de impressão só numa página específica (não no documento inteiro), usar `@page nome { ... }` mais a propriedade `page: nome;` no container da página (ex.: `.print-sheet { page: folha-impressao; }`), em vez de um `@page` global sem nome — Chrome/headless respeitam isso (confirmado gerando PDF com `chromium --headless --print-to-pdf` e inspecionando com `pdfinfo`/`pdftoppm`). Dentro do `@media print`, `break-inside: avoid` em `.card`/`.summary` evita cortar um cartão ao meio entre páginas.
- Qualquer constante pura (mesmo um simples `export const X = false`) que precise ser importada tanto por um Client Component (`app/page.tsx`) quanto por um módulo Server-only (`lib/historico.ts`, que importa `node:sqlite`) deve morar num arquivo à parte sem imports de `node:*` (ex.: `lib/sensivel.ts`), reexportado pelo módulo Server-only para satisfazer o contrato de onde a AC pede a constante. Mesmo princípio já usado em `lib/formato.ts` (US-012): nunca importar de um arquivo com `node:sqlite`/`node:fs` a partir de um "use client".
- `eslint-plugin-react-hooks@7` (via `eslint-config-next`) faz uma análise de estabilidade rasa para `react-hooks/exhaustive-deps`: uma função declarada no corpo do componente (ex.: `gerar`) que só chama setters de `useState`/`fetch` é tratada como estável e não precisa entrar no array de dependências de um `useEffect` que a referencia — mas se essa função chamar OUTRA função também declarada no corpo do componente (ex.: `gerar` chamando `carregarHistorico()`), a análise não desce mais um nível e passa a tratar `gerar` como instável, acusando "missing dependency" no efeito que a usa. Correção: evitar que uma função "estável" (chamada dentro de um efeito) chame outra função irmã do componente; inline a chamada (repetir o `fetch(...).then(setState)` em vez de extrair para uma função e chamá-la de dentro de `gerar`) resolve sem precisar de `useCallback` (não usado em nenhum lugar deste projeto).

## [2026-09-12] - US-001
- Corrigido o bug do atalho `?exemplo=1` em `next dev` (React Strict Mode) nos 10 apps da suíte.
- Causa raiz: o `useEffect` marcava `autoEnviado.current = true` de forma síncrona e retornava um `cleanup` que cancelava o `setTimeout` (`return () => clearTimeout(t)`). Em Strict Mode (dev), o efeito roda: setup → cleanup → setup novamente. O cleanup cancelava o timer agendado na primeira chamada; na segunda chamada do setup, o guard `autoEnviado.current` já estava `true`, então o timer nunca chegava a disparar.
- Correção: manter a marcação do ref antes do `setTimeout` (para não duplicar em Strict Mode), mas remover o `return () => clearTimeout(t)`. Assim o único timer agendado (o da primeira invocação do efeito) sobrevive ao ciclo de desmontagem simulada do Strict Mode e dispara normalmente; a segunda invocação do efeito é bloqueada pelo guard e não agenda um segundo timer.
- Arquivos alterados: `pdi-time/app/page.tsx`, `agente-kanban/app/page.tsx`, `contratos-ia/app/page.tsx`, `entrevista-ia/app/page.tsx`, `financas-ia/app/page.tsx`, `posts-sociais/app/page.tsx`, `prospeccao-ia/app/page.tsx`, `reunioes-ia/app/page.tsx`, `voz-do-cliente/app/page.tsx`, `whatsapp-atendente/app/page.tsx`.
- Não toquei no outro `useEffect` de `agente-kanban` (carregamento inicial do quadro, linha ~43) pois não faz parte do atalho `?exemplo=1` e está fora do escopo da história.
